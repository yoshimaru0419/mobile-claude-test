# 00-workflow: 工程の順序とゲート

## 工程の順序
1. 要件ヒアリング（ユーザーと対話）→ 要件定義書を Confluence にまとめる
2. 要件定義書をもとに、**全工程分**のタスクを Jira に起票する
3. 工程順に実行する: 基本設計 → 詳細設計 → 実装 → 単体テスト
4. 各工程の終わりに、ユーザーの承認を得てから、次の工程へ進む

## 各工程の入口と出口
| 工程 | 入口の条件 | 出口の条件（成果物） |
| --- | --- | --- |
| 要件ヒアリング | ユーザーの依頼 | 要件定義書（Confluence）。ユーザーの承認 |
| 計画 | 承認済みの要件定義書 | 全工程分のタスクが Jira にある。要件IDの対応漏れがない |
| 基本設計 | 計画が承認済み | 基本設計書（Confluence）。承認 |
| 詳細設計 | 基本設計が承認済み | 詳細設計書（Confluence）。承認 |
| 実装 | 詳細設計が承認済み | コードが PR になっている。承認 |
| 単体テスト | 実装が承認済み | テストが通り、単体テスト報告書（Confluence）がある。承認 |

## 守ること
- 前の工程が承認されていなければ、次の工程に着手しない。
- 工程で発生する文書は、Confluence にまとめる。テンプレート（`.claude/templates/doc/`）を使う。
- 状態は Jira のステータスに反映する（`20-atlassian.md` 参照）。
- 迷ったら、推測で進めず、`ai-dev-start` スキルで状態を確認する。

## 飛ばしてはいけない点
- 要件IDとの対応づけ（設計・実装・テストのすべてで）
- reviewer による独立レビュー（文書の確定前）
- 書き込み後の取得検証
