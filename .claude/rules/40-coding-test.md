# 40-coding-test: 実装と単体テストの基準

## 言語・フレームワーク
- **決め打ちしない。** 要件と既存のコードから、最も素直な選択を提案し、ユーザーの承認を得る。
- 決まったら `.claude/project.json` の `stack` に記録する（言語、フレームワーク、テストコマンド）。
- 外部依存の追加は、事前にユーザーへ相談する。

## 実装
- 設計書（基本設計・詳細設計）に沿って実装する。設計と異なる場合は、先に設計書を直す。
- 1タスク = 1コミットで、小さく進める。
- 画面（DOM など）と計算・業務ロジックを分け、ロジックを単体でテストできる形にする。

## 単体テスト
- **要件IDごとに、最低1件の単体テスト**を用意する。
- 正常系に加え、境界値・異常系（例: ゼロ除算、空入力）を含める。
- 実装を書いた担当と、テストを書く担当（`test-writer`）を分ける。実装に引きずられないようにするため。
- テストは、ローカルで実行して通ることを確認してから、PR にする。
- 結果は、単体テスト報告書のテンプレートに沿って、Confluence にまとめる。

## 完了の条件
- テストが通る
- 要件IDと、設計・実装・テストの対応表に、漏れがない
