# 30-git: ブランチ・コミット・PR

## ブランチ
- 作業ブランチは、必ず `develop_v2` から派生する。
- 命名: 機能追加は `feature/**`、ドキュメントは `doc/**`。
- ブランチは、PR の単位（【ルール】【スキル】など）で1本とする。

## コミット
- **タスク（Jira）ごとに1コミット。**
- 件名は `<Jira キー>: <内容>`（例: `API-31: CLAUDE.md を AI駆動開発向けに整備`）。
- コミットメッセージの末尾に、共同作成者とセッションの行を付ける。

## PR
- 向け先は `develop_v2`。
- タイトルは `【<単位>】<要約>`（例: `【ルール】承認・Atlassian・Git の規約`）。
- 本文には、概要・コミットと Jira の対応表・確認内容を書く。リポジトリに PR テンプレートがあれば、その構造に従う。
- **マージは、ユーザーの指示があるときだけ行う。**

## してはいけないこと
- `develop_v2` / `staging` への直接 push
- 履歴の書き換え（強制 push、リベース）。ユーザーの許可がある場合を除く
- 空コミットで CI を動かすこと
