# implement-with-tests: 実装と単体テスト

## 前提
- 詳細設計が承認済みであること。
- 言語・フレームワークが `.claude/project.json` の `stack` に記録されていること。**未決なら、実装を始めずに**、要件と既存コードから最も素直な案を提示して、ユーザーの承認を得て記録する。

## 手順
1. **ブランチ:** `develop_v2` から `feature/<名前>` を作る（`.claude/rules/30-git.md`）。
2. **タスクの確認:** 対象の Jira タスクを「進行中」にする。
3. **実装:** `implementer` が、詳細設計に沿って実装する。画面と業務ロジックを分ける。タスクごとに1コミット（件名の先頭に Jira キー）。
4. **単体テスト:** `test-writer` が、設計書と要件から、要件IDごとに最低1件のテストを書く。正常系・境界値・異常系を含める。
5. **ローカルで確認:** `stack.testCommand` でテストを実行し、通ることを確認する。ビルド確認がある場合は、それも通す。
6. **レビュー:** `reviewer` に、要件IDとの対応漏れを確認させる。
7. **報告書:** テスト結果を、単体テスト報告書のテンプレートで、Confluence に登録する（`doc-writer` → `atlassian-writer`）。
8. **PR:** `develop_v2` 向けに作成する。本文に、コミットと Jira の対応表、確認内容を書く。マージは、ユーザーの指示があるときだけ。
9. **承認:** `approval-gate` で、ユーザーに承認を依頼する。

## 守ること
- テストを通すために、期待値を安易に変えない。
- 外部依存の追加は、事前に相談する。
- 保護ブランチへの直接 push、履歴の書き換え、削除をしない。
