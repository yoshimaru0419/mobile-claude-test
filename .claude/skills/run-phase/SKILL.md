# run-phase: 1工程の標準手順

## 前提
- 前の工程が「完了」（承認済み）であること。そうでなければ着手しない（`.claude/rules/00-workflow.md`）。
- 対象の工程のタスクが、Jira にあること。

## 手順
1. **着手:** 対象タスクを「進行中」にする（`atlassian-writer`）。
2. **成果物を作る:**

| 工程 | 担当 | 成果物 |
| --- | --- | --- |
| 基本設計 | `doc-writer` | 基本設計書（テンプレート使用） |
| 詳細設計 | `doc-writer` | 詳細設計書（テンプレート使用） |
| 実装 | `implementer`（`implement-with-tests` スキル） | コード（PR） |
| 単体テスト | `test-writer` | テストと単体テスト報告書 |

3. **レビュー:** `reviewer` に、要件の対応漏れ・矛盾・未決事項を確認させる。指摘は直す。
4. **登録:** 文書は、`atlassian-writer` が Confluence に登録する（同名ページの確認・整形式の確認・取得検証）。ページ ID を `.claude/project.json` に記録する。
5. **承認待ち:** 工程の全タスクが終わったら、Jira を「承認待ち」にして、`approval-gate` でユーザーに承認を依頼する。
6. **完了:** 承認を受けたら「完了」にして、次の工程へ進む。差し戻しなら「進行中」に戻して、手順2へ。

## コミットと PR
- タスクごとに1コミット（件名の先頭に Jira キー）。PR は工程の単位。マージは、ユーザーの指示があるときだけ（`.claude/rules/30-git.md`）。

## 中断への備え
- タスクの完了ごとに、進捗ファイルを更新して push する（`.claude/state/README.md`）。
