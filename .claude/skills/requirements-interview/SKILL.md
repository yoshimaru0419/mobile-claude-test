# requirements-interview: 対話による要件定義

## 前提
- 対話と承認の受け取りは、**メインのセッション**が行う（サブエージェントはユーザーと対話できない）。
- 質問は**選択式を中心**にし、聞く項目は下記の固定リストに従う（結果のぶれを減らす）。

## 聞く項目（固定リスト）
1. 目的と背景（何のためか）
2. 利用者と利用シーン
3. 対象範囲と対象外
4. 機能の一覧と優先度（必須 / 任意）
5. 画面・インターフェースの要件
6. 非機能要件（実行環境、性能、保守性、対応環境）
7. 開発プロセス上の制約（ブランチ、CI、テスト）
8. 受入条件（操作と期待結果）
9. 言語・フレームワークの方針（未決でもよい。決め方を確認）
10. 未決事項

## 手順
1. 既存のコードや文書があれば、先に読む（`requirements-analyst` に分析させてもよい）。
2. 項目ごとに、選択肢つきで質問する。1回の質問は最大4つ程度にまとめる。
3. 答えから、機能要件に ID（F-01…）を振る。
4. `.claude/templates/doc/要件定義書.html` を使って、`doc-writer` に下書きを作らせる。
5. `reviewer` に、対応漏れ・矛盾・未決事項を確認させる。
6. 指摘を直し、`atlassian-writer` に Confluence へ登録させる（同名ページの確認、整形式の確認、取得検証）。
7. ページ ID を `.claude/project.json` の `confluence.pages.requirements` に記録する。
8. `approval-gate` で、ユーザーに承認を依頼する。

## 守ること
- 推測で埋めた箇所は「（仮）」と書き、未決事項にも挙げる。
- 承認前に、次の工程（`plan-tasks`）へ進まない。
